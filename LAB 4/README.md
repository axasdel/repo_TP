## *Реализация паттернов*

### STRATEGY

**Смысл:** определение семейства алгоритмов, инкапсуляция каждого из них и обеспечение их взаимозаменяемости. Позволяет изменять алгоритмы независимо от клиентов, которые ими пользуются.

**Файлы:** `strategy/*.java`

**Классы:**
- `SortingStrategy`: интерфейс стратегии
- `BubbleSortStrategy`, `QuickStrategy`: конкретные стртегии/алгоритмы
- `Sorter`: контекст, использующий стратегию
- `Main`: клиент 

**Вывод:**

```
пузырьковая сортировка
быстрая сортировка
```

### CHAIN OF RESPONSIBILITY

**Смысл:** передача запросов по цепочке обработчиков, где каждый обработчик решает, может ли он обработать запрос сам или нужно передать его следующему обработчику.

**Файлы:** `chain_of_responsibility/*.java`

**Классы:**
- `Request`, `RequestType`: запрос и типы запроса

- `Handler`: интерфейс обработчика

- `ConcreteHandlerA`, `ConcreteHandlerB`: конкретные обработчики

- `Main`: клиент

**Вывод:**

```
обработчик а взялся за запрос
обработчик б взялся за запрос
запрос TYPE_C не обработан, это конец цепочки
```

### ITERATOR

**Смысл:** предоставление способа последовательного доступа к элементам составного обьекта независимо от его реализации

**Файлы:** `iterator/*.java`

**Классы:**
- `Iterator`: интерфейс итератора

- `ArrayIterator`: конкрентный итератор для массива

- `IterableCollection`: интерфейс коллекции 

- `ArrayCollection`: конкретная коллекция

- `iterator_pattern`: клиент

**Вывод:**

```
а
б
в
```
